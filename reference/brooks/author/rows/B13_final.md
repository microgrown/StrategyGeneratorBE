## Notes for the orchestrator

- The three rules B01 and B02 blocked (`StairsPattern`, `ShrinkingStairs`, `TrendLineSlopeFlattening`) are unblocked exactly as ratified: the pivot scan is INLINED, following `rules/ThreePushPattern.json` and `rules/ThreePushSlopeBias.json` statement for statement, so the only unmeasured thing in the register — the `SwingHigh`/`SwingLow` function's Occurrence 3+ argument — is never asked for. What the twins do use (`for`/`to`, `if`/`then`, price-series subscripts, the relational operators) is registered, and the scan reproduces the MEASURED pivot test: at-or-above the `strength` OLDER bars, STRICTLY above the `strength` NEWER bars, lag exactly `strength`, offsets `strength..lookback-1`, deepest bar touched `lookback - 1 + strength`, `-1` sentinel initialised and every use gated on the pivot count. No `Break` in the EL twins (unregistered), so both twins run their loops to the end and use `< 3` / `< 4` guards.
- No `ASSUMED` register row is leaned on. Words used: `high`, `low`, `close`, `volume`, `highest`, `lowest`, `marketposition`, `if`/`then`/`begin`/`end`/`for`/`to`/`true`/`false`, `and`/`or` — all VERIFIED or ACCEPTED. No `xaverage`/EMA read anywhere in the slice, so the still-unrun `EL_XAverage_Lag_Probe` does not touch it; no `TLValue` CALL either, only its measured slope arithmetic.
- Outside the EL translation table: nothing. No `classMembersHook`, no `std::` containers, no ternaries, no lambdas. The only C++-only constructs are the loop-local `int j` / `int k` / `bool okHi` / `bool okLo` inside the hook loops, as `ThreePushPattern` already has.
- DOUBLE PLACEMENT: no C++ scratch is declared at hook scope in any of the five — every scratch value is a `localVariables` entry, and `(int)pivotStrength` / `(int)pivotLookback` are written inline in the loop bounds rather than hoisted into a `const int`.
