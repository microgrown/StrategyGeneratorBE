# Slice 15 — the EMA's lagged reads

CATALOG rows for `reference/brooks/author/slices/15_ema_lagged.json`, the nine
A-list and three B-list rules held back until `XAverage(...)[k]` was measured.
Measurement: `reference/brooks/probes/XAVERAGE_LAG_FINDINGS.md` (2026-09-17) —
the function's `[k]` history is bit for bit what it printed k bars earlier, and
reads before that history exists return **0.0**, so the corpus's zero-initialized
mirrored buffer is exact and every rule here **guards its own first k bars**
(`CurrentBar > k` in EL, `ctx.CurrentBar()` in C++) instead of comparing against
that zero. `emaLength` is a normal optimizer input in all of them: the wrapper
recomputes SF on a length change and carries its state, measured on the same run,
and the "pin `emaLength`" caveat is retired. Table format is `rules/CATALOG.md`'s.

| Rule | Type | Sides | Reaches back | Inputs | Fires when |
|---|---|---|---|---|---|
| `BarsBeyondEmaCount` | Entry | mirrored | `lookback - 1` | `lookback(10)`, `minBarsBeyond(7)`, `emaLength(20)` | At least K of the last N bars closed above the EMA (long) / below it (short) — the authorable stand-in for Brooks's always-in direction, stateless, so it re-reads the window every bar rather than latching and drifts at the edges of a trend where a state machine would hold. Not `CloseAboveAverage`, which tests ONE bar against its own SIMPLE average; this counts bars beyond an EXPONENTIAL one, so a single bar crossing back barely moves it. `CountIF(Close > ema, lookback)` counts bars 0..N−1 INCLUDING the current bar and its counted condition is a TRUE SERIES (VERIFIED), so position i tests `Close[i] > ema[i]` — every counted bar reads the EMA at its own offset, which is exactly what the mirrored ring buffer supplies. Both counts accumulate in ONE pass so neither side's loop can run a different number of times from EasyLanguage's. `WFSafe_Xaverage` mirror from `EmaGapBar` (price seed on the study's first calculated bar, `X = X[1] + SF*(P − X[1])` as ONE statement, `SF = 2/(emaLength+1)`, no warm-up hole on the CURRENT value). Deepest lagged read `ema[lookback − 1]`, so the rule is silent for its first `lookback − 1` bars in BOTH twins; the EMA itself is recursive state rather than a window, but it never forgets its seed, so Max Bars Back and the chart start are part of the specification |
| `ConsecutiveClosesBeyondEmaRun` | Entry | mirrored | `strongBars - 1` | `emaLength(20)`, `strongBars(20)` | EVERY one of the last N bars closed above the EMA (long) / below it (short) — Brooks's "very strong trend" (TP4-14, p365), at which point he blocks countertrend trades entirely. A single close back through the average resets it, which is the whole difference from `BarsBeyondEmaCount`: one gap bar and a run of twenty are two rules. SUPERSET RELATION, flagged deliberately: `BarsBeyondEmaCount` at `minBarsBeyond = lookback` IS this rule — but that is a COUPLING of two inputs, not a pinned value, and the grid sweeps each input independently, so reaching it there means pinning both to one number and losing the sweep. Authored separately on that ground, the same one that puts `DualMomentum` beside `Momentum`. Written as a `CountIF` against the window length rather than an all-of-N early exit: EasyLanguage does not short-circuit, the count can never exceed the window, and `>= strongBars` is the source's "all of them" without a float equality (the `ExitOnFirstOppositeBodyAfterRun` spelling). Same `WFSafe_Xaverage` mirror and mirrored history; deepest lagged read `ema[strongBars − 1]`, guarded |
| `EmaGapBarBreakoutEntry` | Entry | mirrored | `1` | `emaLength(20)` | The PREVIOUS bar never touched the EMA — its whole range sat below the average — and this bar closes above that bar's high: Brooks's moving-average-gap-bar fade, bought with the trend; short is the mirror. Eight restatements across the three volumes. CARRIED WHOLE: `CloseAbovePriorHigh(lookback = 1)` is exactly the breakout half, but the gap-bar half cannot come from a second pane because `EmaGapBar` evaluates at bar 0 and this needs it at bar 1, and the panes AND same-bar conditions only. Everything the sources wrap around it IS a separate pane and is left out — the strong-trend precondition is `BarsBeyondEmaCount` or `EmaGapBarRun`, the bear-body requirement on the gap bar is `StrongTrendBar` at `lag = 1`; the "FIRST gap bar since the trend began" qualifier is dropped as unmechanizable without a trend origin, and the trailed sell stop of one source collapses under the standing signal-bar-close / next-bar-open convention. `emaPrev` is captured at the TOP of the hook before the update — the plain `TwentyGapBarPullbackEntry` capture — so it holds the EMA at the end of the previous bar, which is what EL's `ema[1]` reads, and 0.0 on bar 1, which is also what EL returns there; `CurrentBar > 1` guards that one bar |
| `CloseCrossesEma` | Entry | mirrored | `1` | `emaLength(20)` | The previous close was at or below the EMA and this close is above it (short: the mirror) — Brooks's "the first close below the moving average" after a run on the other side. **WRITTEN AS THE TWO-BAR EVENT TEST, NOT EL's `crosses above`**, and that is the rule's specification rather than a translation choice: the merged pseudocode is the two-bar test and its merge notes contrast it with `MovingAverageCross` precisely because that rule goes through the bridging state machine and this one does not; `crosses above` is VERIFIED as a STATE MACHINE that fires against the most recent NON-equal side, however many bars back, and BRIDGES an equality run so above → equal → above does not re-fire, which is a different set of bars and therefore a different rule; and this rule was on the blocked-on-lagged-read list at all only because the two-bar form needs `ema[1]` — the crossing form reads only current values and would never have been blocked. The register's REFUTATION of `el_gt(A,B) && el_le(A[1],B[1])` is a refutation of that expression AS A MIRROR OF THE WORD `crosses`; neither twin uses the word, so nothing is being mirrored and both twins spell the same two-bar test. Consequence stated rather than hidden: an equality run re-fires here where `crosses` would bridge it, which for a close against an EMA costs bars only inside EL's 2.22e-12 relational tolerance. Not `CloseBeyondEma`, which is the STATE where this is the EVENT — what `MomentumChange` is to `Momentum`; not `MovingAverageCross`, which crosses two SIMPLE averages. Never split: a crossing is inherently two-bar. `CurrentBar > 1` guards the bar on which `ema[1]` is the pre-history zero — without it the short side would fire spuriously on a positively priced series, where `Close[1] >= 0` always holds |
| `NoTwoConsecutiveClosesBeyondEma` | Entry | mirrored | `lookback - 1` | `emaLength(20)`, `lookback(2)` | Nowhere in the last N bars did two bars IN A ROW close below the EMA (long) / above it (short) — one of Brooks's listed signs of a strong trend, stated verbatim in all three volumes. A SINGLE close on the wrong side survives it, which is exactly what distinguishes it from `BarsBeyondEmaCount`. At the default `lookback = 2` there is one pair and no loop at all, the literal reading of "no two consecutive"; the sources' 10- and 20-bar window forms are the same rule at a larger `lookback`. **`lookback` must be at least 2** — at 1 there is no pair and EL's `CountIF` window would be 0 — so the grid's start value is 2. The STRADDLE misreading (one close above, one below) is a different set of bars and is not carried, and the "both bars must be trend bars" qualifier of one source is dropped because a per-bar body test inside the scan cannot be supplied by a separate pane. `CountIF(Close < ema and Close[1] < ema[1], lookback - 1)` uses the VERIFIED shifting-offset series semantics, so position i tests the pair (i, i+1); a count is a non-negative integer, so `<= 0` is "none" without a float equality. Same mirrored EMA history; deepest lagged read `ema[lookback − 1]`, guarded |
| `PullbackDepthBeyondEma` | Entry | mirrored | `max(lookback - 1, atrLookback + 1)` | `emaLength(20)`, `lookback(20)`, `maxDepthAtr(1.0)`, `atrLookback(14)` | No close in the last N bars fell more than K ATRs BELOW the EMA (long); the short side is the mirror above it — the pullbacks have stayed shallow. TP3-36's definition: one `Lowest` over the derived series `Close − ema`, compared against an ATR-scaled depth, and the same measurement covers the whole family at different depths and senses — "the average held as support" is `maxDepthAtr` near 0, and "the bears pushed a pullback well below the moving average" is this rule NEGATED at about one ATR. RECORDED LOSS: two sources measure the window's lowest LOW, not the lowest close, so a wick through the average counts for them and not here; the close was chosen because TP3-36 is the only source that states a depth at all and because `EmaTouch` already carries the wick question. The "each pullback deeper than the last" reading needs the previous pullback's depth retained across bars and is kept only as a citation. Not `CloseWithinAtrOfEma`, which bands the CURRENT close symmetrically and says nothing about a window; not `CloseBeyondEma`, a single bar. `Lowest`/`Highest` bottom out in `Extremes`, EL source — seeded at offset 0, scanning 1..Length−1, strict comparison — and the loop is written in that shape, both extremes from ONE pass; the scanned argument is an expression over a price series AND a variable, so at offset i it is `Close[i] − ema[i]`, which the mirrored history supplies. ATR is the `WFSafe_AvgTrueRange` rolling accumulator, ONE call site in the hook. Deepest lagged read `ema[lookback − 1]`, guarded |
| `EmaSlope` | Entry | mirrored | `max(slopeLookback, atrLookback + 1)` | `emaLength(20)`, `slopeLookback(5)`, `slopeAtr(0.5)`, `atrLookback(14)` | The EMA has risen by at least K ATRs over the last N bars (long), fallen by as much (short) — a steeply sloping moving average. Not `Momentum`, which compares the CLOSING PRICE with the close N bars ago: this compares the EMA with ITS OWN value N bars ago and adds a threshold, so it is smoother and fires on a different set of bars. Kept apart from `EmaFlat` — `|slope| <= T` and `slope >= T` are not each other's negation, so the per-placement negate toggle cannot produce one from the other. TICKS → ATR: the source's 20-tick threshold is restated in ATRs because `MinMove`/`PriceScale` are unregistered and the engine exposes no tick size, the substitution `CloseBeyondEma` and `PriorSessionLevelTest` make; Brooks gives no number for "steeply up" at all, so `slopeAtr` is an optimizer input. The source's `priorSessionEndOffset` (measure yesterday's slope, trade today) is dropped — a session-anchored offset for no stated benefit, and the slope is persistent enough that reading it on the current bar is the same information. History depth is `slopeLookback + 1` so lag 0 and lag `slopeLookback` both live in the buffer and `slopeLookback = 0` collapses to the current value, as EL's `ema[0]` does. `WFSafe_AvgTrueRange` rolling accumulator, ONE call site. Deepest lagged read `ema[slopeLookback]`, guarded |
| `EmaFlat` | Entry | same | `max(slopeLookback, atrLookback + 1)` | `emaLength(20)`, `slopeLookback(5)`, `flatAtr(0.25)`, `atrLookback(14)` | The EMA has moved less than K ATRs over the last N bars in either direction — "the moving average is relatively flat", a trading-range clue. DIRECTION-AGNOSTIC, so both sides are identical text: a distance carries no direction. Both sources give the same lagged-difference test over 5 bars and neither gives a cutoff (one leaves it literally null, the other guesses 2 ticks), so `flatAtr` is an optimizer input stated in ATRs for portability — `MinMove`/`PriceScale` are unregistered. Brooks uses it as one clue among several for a trading-range day, never alone; the rest of that read (a first-bar doji, yesterday's closing range) is other rules' and ANDs in the pane. Kept apart from `EmaSlope` for the same reason that row gives. `AbsValue` in EL, `std::fabs` in C++. Same history depth `slopeLookback + 1` and the same `WFSafe_AvgTrueRange` single call site; deepest lagged read `ema[slopeLookback]`, guarded |
| `BuyLimitBelowRisingMA` | Entry | mirrored | `maSlopeLookback` | `emaLength(20)`, `maSlopeLookback(10)`, `minMaSlopePerBar(0.5)`, `intervalDistance(1)` | The EMA is rising at least `minMaSlopePerBar` PRICE POINTS per bar over the last N bars and this bar trades down to `intervalDistance` points below it (short: the mirror above a falling average) — a buy limit resting under a steeply rising moving average. THE LIMIT ORDER under the corpus's standing signal-bar-close / next-bar-open convention: an order at a level is taken as filled on the bar that trades to the level, so the test is `Low` against a level read from the SAME bar's EMA. That is a deliberate change from the merged pseudocode, which paired `low[1]` with the current bar's average — yesterday's low against today's level, a lag with no stated purpose; `TrendLineTouch` made the same substitution for R28-38's limit order at the line. THE LADDER IS DROPPED: the source places `numScaleInLevels` limits at successive intervals, a multi-unit scale-in the engine cannot hold as one position, and this is that ladder at one level. EQUALS TWO PANES, recorded rather than hidden: `EmaSlope` ANDed with the limit touch, up to the unit change — `EmaSlope`'s threshold is a TOTAL move in ATRs, this one the source's PER-BAR slope in price points — and it is carried whole on the `EecBooksCanBeGreat` precedent, one named order placement stated by one source. A PRODUCT, NEVER A QUOTIENT: the source divides the EMA's move by `maSlopeLookback` and EasyLanguage raises a runtime divide-by-zero, so the per-bar floor is multiplied back out. `intervalDistance` is in PRICE POINTS, not ticks. `emaLength` is absent from the merged parameter list — the source says only "the moving average" — and is added at the corpus default of 20. Deepest lagged read `ema[maSlopeLookback]`, guarded |
| `BarsSinceEmaCross` | Entry | mirrored | `1` (plus the two counters carried in locals) | `emaLength(20)`, `minTrendBars(30)` | The close last crossed UP through the EMA at least N bars ago (long); the short side counts down-crosses — the trend is mature, Brooks's 30 bars. His use is a warning as much as a signal — a trend that old often breaks out unusually strongly but may equally be an exhaustion climax — so whether a placement takes it or negates it is the author's call. TP3-30 offers two proxies for trend age; the cross counter wins over the bar offset of the window's lowest low because it needs no `Lowest` window, reuses `CloseCrossesEma`'s test as its reset, and degrades gracefully in a range, where the counter simply stays small. Distinct from `EmaGapBarRun`, which counts bars since the average was TOUCHED by a bar's range rather than since the close last crossed it. The cross test is `CloseCrossesEma`'s, INLINED as the corpus does with composites — the two-bar EVENT, not `crosses above`, for the reasons that row records — and guarded on the one bar where `ema[1]` is the pre-history zero so no cross can be manufactured there. The counters are plain locals holding their own previous value (the pseudocode's `barsSinceCrossUp[1] + 1`), start at 0 and are reset by nothing but a cross, so before any cross has been observed they simply count bars since the strategy's first bar: the pseudocode read literally, and a market that has never crossed has not crossed recently either. Only `ema[1]` is read |

## Notes for the orchestrator

- **The `CloseCrossesEma` spec question is answered in its row and its hooks:**
  the two-bar event test, not `crosses above`. The previous pass
  (`rows/15_ema_swing.md`) left it open because the crossing formulation would
  have unblocked the rule without the lagged read; now that the lag is measured
  there is no reason to change the spec, and `crosses` demonstrably fires on a
  different set of bars (it bridges equality runs and looks back to the most
  recent non-equal side). `BarsSinceEmaCross` inlines the same choice.
- **`ConsecutiveClosesBeyondEmaRun` and `BarsBeyondEmaCount` were checked
  against each other and both kept.** The first is the second at
  `minBarsBeyond = lookback`; that is a coupling of two inputs, which no grid
  can express while still sweeping the run length. If the orchestrator would
  rather carry one rule, `BarsBeyondEmaCount` is the survivor and every grid
  using it as a streak test must pin both inputs to the same single value.
- **No rule here leans on an ASSUMED register row.** Every word used is VERIFIED
  or ACCEPTED: `wfsafe_xaverage`, `wfsafe_avgtruerange`, `countif`, `crosses`
  (not used — recorded only), `highest`/`lowest`, `absvalue`, `currentbar`,
  `close`/`open`/`high`/`low`.
- **Outside the EL translation table:** the `std::vector<double>` /
  `std::size_t` ring buffer that mirrors the EL variable's own history, and
  `std::fabs` for `AbsValue`. Both are `BarRangeAboveStd`'s precedent, and
  `validateRule` warns "unusual local type" on the first for the same reason it
  warns on that rule.
- **Grid constraints the rows carry:** `lookback >= 2` in
  `NoTwoConsecutiveClosesBeyondEma`; `emaLength` is now a free optimization axis
  everywhere (the pin caveat is retired for the whole EMA family, including the
  five current-bar rules whose `rows/15_ema_swing.md` rows still say "pinned").
