# Slice B03 -- three-push patterns, wedges and final flags

CATALOG rows for the rules written from `slicesB/B03_three_push_patterns.json`,
bucket `three_push_patterns`. Table format is `rules/CATALOG.md`'s.

`ThreePushPattern` is the base of the family and is the first row: it is a
`depends_on_keys` entry for nine of the slice's rules but appears in neither
`B_KEYS.md` nor `rules/CATALOG.md`, and the slice brief asked for it first. Every
other rule in the slice INLINES its pivot scan rather than referencing the file,
as `BreakoutLevelRetest` inlines `SwingHigh`'s.

The scan is hand-written rather than calling `SwingHigh(1..3, ...)` because the
`swinghigh` register row lists **Occurrence 3 and above as unmeasured**, and the
third push is the whole point of the pattern. It reproduces the measured pivot
test exactly (`EL_Swing_Probe.txt` / `el_swing_output1.txt`): at or above the
`swingStrength` older bars, strictly above the `swingStrength` newer bars,
confirmation lag exactly `swingStrength`, candidate offsets
`swingStrength .. lookbackBars - 1`, `-1` sentinel guarded, and the deepest bar
touched `lookbackBars - 1 + swingStrength`. It is written without `Break`, which
is not a registered EasyLanguage word, so both twins run the loops to the end
with a `< 3` guard.

## Not written

- `HighThreeEntry` -- duplicate of `HighLowBarCount` (slice B06) at `countTarget = 3`. That rule's inputs are `resetLookback(20)` and `countTarget(2)`, and it fires on the bar the counter ADVANCES to `countTarget` (`advHigh && highCount == countTarget`), which is exactly this rule's `highLowBarCount[0] == 3 && highLowBarCount[1] == 2`. V00-54's High 4 is the same rule at `countTarget = 4`. An existing rule at a fixed parameter, per the skill's third duplicate test; confirmed against `rules/HighLowBarCount.json` on disk after the orchestrator's note.

## Notes for the orchestrator

- `ThreePushPattern` is written but is NOT in `B_KEYS.md` or the slice's `rules`
  list -- it appears only as a `depends_on_keys` entry, and the slice brief
  directed that it be authored first. Its CATALOG row is above; drop it if the
  key is meant to stay unclaimed.
- `ThreePushDurationWindow` and `CorrectionBarsFractionOfPattern` are authored
  **mirrored** where the slice records `sides: same`. Both read the pattern's
  pivots, and a bottom's pivots are lows while a top's are highs, so identical
  text on both panes would read the wrong series on one of them.
- `FinalFlagReversalBreakoutEntry`'s merged pseudocode measured the flag and the
  prior breakout over overlapping windows, which can never be satisfied (the
  flag's extreme is at or beyond any breakout inside it). The flag window is
  offset back by `priorBreakoutWindow` when the term is switched on.
- Three rules promote inputs the slice did not list, all forced by the
  mechanization: `lookbackBars(40)` on `ThreePushDurationWindow`,
  `CorrectionBarsFractionOfPattern` and `SwingPivotTarget` (the pivot scan needs
  a window), and `consecutiveBars(2)` / `bodyFraction(0.6)` /
  `tailFraction(0.2)` wherever the always-in state machine is inlined.
- `shapeMode` on `ThreePushPattern` is new: it is how the expanding triangle and
  the converging wedge share one rule.
