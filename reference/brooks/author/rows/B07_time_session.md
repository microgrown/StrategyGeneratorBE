# Slice B07 — time_session

CATALOG rows for the twelve rules of `reference/brooks/author/slicesB/B07_time_session.json`.
All twelve were written; both twins exist for each.

| Rule | Type | Sides | Reaches back | Inputs | Fires when |
|---|---|---|---|---|---|
| `SessionOpeningRange` | Entry | same | 1 | `openingBars(12)` | The session's opening range is SET, i.e. the session is at least `openingBars` bars old. The corpus's session primitive: the first `openingBars` bars fix `orHigh`, `orLow` and `orHeight`, which stay frozen for the rest of the session; every other opening-range rule INLINES this same block rather than referencing the file, as the corpus does with named composites. Session model per the standing decision — a session starts when the wall-clock close date changes, EL `date > date[1]` mirrored as `day_of(ctx.Time(0)) > day_of(ctx.Time(1))` (the same slicing `CloseWithinAtrOfVwap` and `OpeningRangeBreakout` use, and the boundary the xxxD family carries) — with the running high/low and a bars-into-session counter in locals reset on that change. `barsIn` is 1 on the session's first bar, matching `OpeningRangeBreakout` and `FailedBreakoutOfPriorSessionExtreme`. Book values for `openingBars` disagree (5-10 bars, "30 to 60 minutes" = 12 five-minute bars, "the first hour or two" = 24), so it is an optimizer input at 12; the bar-count form beats Brooks's clock form because it survives a change of bar interval and needs no session-open time input. Warm-up mirrors EL exactly: the counter and extremes hold their initial 0 if the first calculated bar falls mid-session. Intraday bars only |
| `IsFirstBarOfSession` | Entry | same | 1 | — | This bar's wall-clock close date differs from the previous bar's — the structural gate under every opening-bar setup, carried once so first-bar and second-bar setups can AND it in a pane. Not a Brooks statement; it is the definition the rest of the family needs. `date[1]` is the DATA series' real history, so no first-bar guard is needed, exactly as `CalendarBoundaryExit` relies on. Not `CalendarBoundaryExit`, which is the same accessor read as year/month on the Exit side. Intraday bars only — on a daily series every bar starts its own session and the rule is true on every bar |
| `TrendFromOpenFlag` | Entry | mirrored | 1 | — | A per-session flag: set to +1 the first time a bar closes above the session's FIRST bar's high, to −1 the first time one closes below its low, and cleared if price later closes through the other extreme of that same first bar; reset at every session start so it never leaks across days. Brooks's glossary form of trend-from-the-open needs a no-pullback counter, a session-extreme tracker and a persistence test; the chapter's own mechanical proxy is coded instead, and the strict form's extra content — the extreme going unchallenged — is carried by `SessionExtremeSetInOpeningWindow`. The four tests are order-safe: `firstLow <= firstHigh`, so no bar can set and later clear the flag in one pass. No inputs — the first bar's two prices are the whole specification. Intraday bars only |
| `SessionOpenNearSessionExtreme` | Entry | mirrored | `atrLookback + 1` | `nearAtr(0.1)`, `atrLookback(14)` | The session's OPENING price is still within `nearAtr` ATRs of the session's running low (short: of its running high) — Brooks's sign of strength, a day that opens on its low often closing on its high. Stated in hindsight in the source; made real-time by comparing the session open with the low SO FAR, which is monotone: once broken it stays broken for the session. Distinct from `TrendFromOpenFlag`, which needs a CLOSE beyond the first bar's extreme; this needs only the open to remain the session extreme. TICKS → ATR: the source's `nearThreshold` ticks became `nearAtr`, because `MinMove`/`PriceScale` are chart constants and the engine exposes no tick size to a strategy at all — the substitution `PriorSessionLevelTest` and `BreakoutLevelRetest` make, at their 0.1 ATR default. One `WFSafe_AvgTrueRange` call site, in the hook. Intraday bars only |
| `CloseNearSessionRangeMidpoint` | Entry | same | 1 | `middleZoneFraction(0.2)` | The close sits within `middleZoneFraction` of the session's range so far of that range's midpoint — Brooks's middle-of-the-day, middle-of-the-range caution. Placed NEGATED it is "no entry in the middle of the day's range". The source is a composite of a clock window (the book's 8:30-10:30) and this price test; the clock half IS `TimeWindow`, already in the corpus, and the entry pane ANDs, so only the price half is carried — Brooks himself calls the clock half a guideline ("the overriding factor is the price action"). Not `RangeMidpointZone`, which bands the midpoint of a FIXED N-bar window, and not `CloseRangePosition`, which places the close inside its OWN bar: the window here grows through the day and resets at the open, so no `rangeLookback` reproduces it. Written multiplied rather than as a ratio, so a session whose high equals its low fires both sides rather than hitting EL's runtime divide-by-zero. Intraday bars only |
| `MorningLegDirection` | Entry | mirrored | `atrLookback + 1` | `firstHourBars(12)`, `minLegAtr(1)`, `atrLookback(14)` | At exactly `firstHourBars` bars into the session the net move from the session OPEN is measured; if it is at least `minLegAtr` ATRs the leg's direction is LATCHED for the rest of the session (long side: up). Brooks's precondition for a trend-resumption day — "a strong trend in the first hour or so and then a trading range". Latching at a fixed bar count rather than re-evaluating is what makes it a day-type flag: `Momentum` compares the close with the close N BARS ago every bar, this compares it with the SESSION OPEN once. Kept apart from `TrendFromOpenFlag` (only the first bar's extreme) and `OpeningRangeVsAvgDailyRange` (only the opening range's width). A dead-flat leg gives height 0 and fails the threshold, so no sign has to be invented for zero. The `WFSafe_AvgTrueRange` accumulator is advanced UNCONDITIONALLY before the latch — it is rolling and must step exactly once per bar, so it can never sit inside the `if`. Intraday bars only |
| `SessionExtremeSetInOpeningWindow` | Entry | mirrored | `atrLookback + 1` | `firstHourBars(12)`, `nearAtr(0.5)`, `atrLookback(14)` | Past the opening window, the session's low was made INSIDE that window, is still the session low, and price has come back to within `nearAtr` ATRs of it (short: the session high) — "the high or low of the day usually forms in the first hour", used to trade the level as the probable low of the day. The measurable half of the strict trend-from-the-open definition, kept apart from `TrendFromOpenFlag` because it fires on different bars: that flag needs only the first bar's extreme taken out, this needs price back NEAR the level after the window closed. `loBar`/`hiBar` are the bars-into-session indices at which the running extreme was last improved, updated on STRICT improvement so a tie keeps the EARLIER bar — the convention EL's own `Highest`/`Lowest` carry through `Extremes`. Intraday bars only |
| `AverageDailyRange` | Entry | same | `maxScanBars + 1` | `dayLookback(20)`, `maxScanBars(500)` | The mean high−low of the last `dayLookback` COMPLETED sessions is available, i.e. that many completed sessions have been seen. The corpus's second session primitive: `OpeningRangeVsAvgDailyRange` and `AvgDailyRangeFractionStop` inline the same block for the value. Deliberately not an ATR of daily bars — no gap term, because "the range of recent days" is what Brooks's 25/30/50-percent readings are quoted against. Not `AtrFastAboveSlow` or any other corpus volatility measure: those are rolling N-BAR windows, this is a rolling N-SESSION one. Implemented as a BAR SCAN in BOTH twins rather than as `HighD(k)`/`LowD(k)`: those are VERIFIED but have no engine counterpart, so the C++ would have to reconstruct them anyway, and the stateful mirror `FailedBreakoutOfPriorSessionExtreme` uses reaches only ONE prior day. The scan walks back from bar 1, skips bars carrying the current date (so today's incomplete session never enters the average — the result is exactly `HighD(1..dayLookback) − LowD(1..dayLookback)`, the xxxD family's day being the same wall-clock date as `date <> date[1]`), and closes a day group at the oldest bar of each date, which is the `date[kk + 1]` read that sets the reach. The `dayLookback` guard WRAPS the date read rather than being ANDed with it, because EasyLanguage does not short-circuit and the twins must touch the same history. `maxScanBars` must cover `dayLookback` sessions of bars and Max Bars Back must cover `maxScanBars + 1`; on a daily or 1440-minute series one bar is one session, so `dayLookback + 1` is enough and the rule degenerates exactly to `Average(High − Low, dayLookback)` read one bar back. If the scan runs out first the rule is silent, not wrong |
| `OpeningRangeVsAvgDailyRange` | Entry | same | `maxScanBars + 1` | `openingBars(12)`, `lowFraction(0)`, `highFraction(0.3)`, `dayLookback(20)`, `maxScanBars(500)` | The session's opening-range height, as a fraction of the recent average daily range, lies between `lowFraction` and `highFraction`. Under about 0.3 the day is in breakout mode; a third to a half favours a trending trading range day; above about a half the opening move was a spike and the day is likely spike-and-channel. The most-restated idea in the bucket — eight candidates at four thresholds (about 25 percent, under 30 percent, a third to a half, "large") — carried as ONE band rule, since the large-opening-range form is this rule with `lowFraction` raised or the band negated by the per-placement toggle. The spike-DIRECTION term one candidate adds and the climactic-reversal caveat of another are separate concerns and are not carried. `SessionOpeningRange` and `AverageDailyRange` are INLINED, same text as their own files, per the composites decision. Direction-agnostic: a day type is not long or short. Intraday bars only |
| `AvgDailyRangeFractionStop` | Exit | same | `maxScanBars + 1` | `adrFraction(0.6)`, `dayLookback(20)`, `maxScanBars(500)` | Open loss reaches `adrFraction` of the recent average daily range, converted with `BigPointValue` — Brooks's "50 to 75 percent of the average daily range" threshold for deciding the trend is over, used as a protective stop. Book values 0.5 to 0.75; default 0.6. Not `AtrProfitTarget`/`AtrTrailingStop`, which scale by a rolling N-BAR ATR and are a target and a trail; this scales by an N-SESSION high−low range and is a fixed protective stop. The mined candidate was research grade only because "average daily range" was undefined — the `AverageDailyRange` primitive settles it, and its block is inlined here. While the average is not yet available `adrReady` gates the exit, so a warm-up bar cannot exit at a zero distance. `BigPointValue` is the raw multiplier and is NOT currency-converted while `OpenPositionProfit` is, as in `AtrProfitTarget`. Daily-ok: on a daily or 1440-minute series set `maxScanBars` to `dayLookback + 1` |
| `SessionAvgBarRangeStop` | Exit | same | 1 | `stopMultiple(1)` | Open loss reaches `stopMultiple` × the average bar high−low range SO FAR TODAY, converted with `BigPointValue`. Brooks quotes it as "around the height of an average bar so far today, maybe 10 to 15 cents" — the cents are stock-specific, the multiple is the portable form. The window is what makes it its own rule: session-relative and GROWING through the day, one bar wide at the open and reset at the next one, which no setting of `AtrTrailingStop`'s fixed rolling N reproduces, and this is a fixed protective stop rather than a trail. It is a mean of high−low, NOT of true range and NOT the `WFSafe_AvgTrueRange` rolling accumulator — the mining record's `AvgTrueRange` note is misleading. The bars-into-session counter is at least 1 on every evaluated bar, so the division is safe. Intraday bars only |
| `MaxTradesPerSession` | Switch | same | 1 | `maxTradesPerDay(5)` | The number of trades taken in the current session has reached the cap and the strategy is flat — "look for only three to five reasonable trades a day"; book value three to five, default 5. A trade is counted when the position CHANGES to a non-flat state (`mp <> 0 and mp <> mp[1]`), which counts flat→long, flat→short and a REVERSAL, the case that opens a position without passing through flat; `TotalTrades` would have been cheaper but ticks on the EXIT's fill bar, which is not when a trade is taken. The C++ mirrors the EL variable's own one-bar history with a zero-initialized local advanced in `endOfFileHook`, as `MonthlyProfitTarget` does. ENTRIES ONLY, NOT FLAT: a Switch both blocks entries and ORs its condition into the exits, and Brooks means only the first, so the `MarketPosition = 0` term makes the exit half inert — the condition is false while a position is open, and when flat the generated exit is already guarded on `MarketPosition` at signal time. That is the difference from `MonthlyProfitTarget`, the corpus's other Switch, which does force flat. Intraday bars only |
