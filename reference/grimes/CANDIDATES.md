## Design decisions

### 3/10 oscillator canonical form
- **indicators_bands**: options=['Average(close,3) - Average(close,10) with a 16-period simple signal line (Appendix B, G14-01/G14-02)', 'the exponential restatement in the glossary (G16-11)', 'an EL MACD word']; recommended: SIMPLE: osc = Average(close, 3) - Average(close, 10), signal = Average(osc, 16). The merge brief settles it and Appendix B's own text says SMA; G16-11's 'ema assumed by analogy' is a mining guess and loses. el_words_needed is Average — never MACD. The oscillator is a difference of averages of one series, so zero-line tests pass the shift test. Its history is a DERIVED series: mirror it as a zero-seeded ring buffer (AwesomeOscillatorSlope / AtrRising precedent), and guard the warm-up where a Highest or Percentile reads it.; gates: ['OscillatorAboveZero', 'OscillatorZeroCross', 'OscillatorNewExtreme', 'OscillatorPercentileRank', 'OscillatorHook', 'OscillatorSlowLineAboveThreshold', 'OscillatorSlowLineExtendedRollover', 'MomentumDivergenceAtSwingExtreme', 'OscillatorJumpOutOfProportion']

### Accumulation vs distribution (the Wyckoff phase test)
- **ranges_levels_tests**: options=['one composite rule: tight range AND flat moving average AND prior-leg direction', 'three separate panes', 'do not mechanize the phase at all']; recommended: three panes. Two of the three halves already exist - RangeWidthBelowAtrMultiple and EmaFlat - so only the discriminator is new, and it is one lagged close comparison: accumulation is a base with a DECLINE behind it (long context), distribution a base with an ADVANCE behind it (short context). Carry it as one new `lag` input on Momentum (PriorLegDirection). Do not author the composite.; gates: ['PriorLegDirection']

### Band-shaped filters (a quantity with BOTH bounds)
- **pullbacks_continuation**: options=['a second rule file for the upper bound', 'a new input on the rule that already computes the quantity']; recommended: A new input on the existing rule. A band is not the existing rule negated (a bar that never reaches the lower bound fails the band and passes the negation), and the corpus already keeps bands as first-class rules (PullbackNearMissesEntryPrice, ShallowDipBelowPriorBarLow). Four of this bucket's A-list are exactly this: maxRetracementFraction on PullbackDepthFromRecentHigh, minOpposite on OppositeBodyCountInWindow, minRisingLows on HigherSwingLow, atrMultiple on AtrAboveAverage. Every default is chosen inert so existing placements are unchanged.; gates: ['RetracementDepthWithinBand', 'HiddenComplexPullbackBodyCount', 'RisingSwingLowCount', 'AtrAboveAverageMultiple']

### Channel-line construction for Grimes's parallel channel
- **breakouts**: options=["Grimes's PARALLEL channel line (the trend line offset through the opposite pivot)", "the corpus's settled INDEPENDENT two-pivot line through the two most recent same-side pivots (author/DECISIONS.md, slice B01)"]; recommended: keep the corpus's two-pivot construction: it costs no new machinery, the whole ChannelLine* family already uses it, and TrendChannelLineTarget was dropped as a duplicate once it was applied -- so every Grimes channel-line candidate maps onto the existing family rather than adding a parallel projection; gates: ['ChannelLineBreakWithAtrMargin']

### Consolidation length (how long a pause has lasted)
- **ranges_levels_tests**: options=['a run of consecutive bars on which the N-bar range width stays below K x ATR', "a detector that measures each consolidation and remembers the trend's typical length", 'a longer rangeLookback at the same ATR multiple']; recommended: the consecutive-bar run - one new `consecutiveBars` input on RangeWidthBelowAtrMultiple (the MomentumConsecutiveBars precedent). Grimes states a RATIO ('three or four times the normal five to eight bars') and the history of prior consolidation lengths needed for a ratio is machinery no source describes, so bake the ratio into a fixed minimum of about 18 bars and let the grid move it. ONE current ATR read for the whole run, never a lagged read of WFSafe_AvgTrueRange.; gates: ['TightRangeRunLength']

### Fast-line artifact window anchor
- **indicators_bands**: options=['an oscillator zero cross (MovingAverageCross at 3/10)', 'a close cross of the EMA (BarsSinceEmaCross)', 'a confirmed swing pivot']; recommended: the oscillator zero cross, which keeps the rule inside the indicator that produces the artifact and needs only a bar counter. Appendix B fixes the window at slowLen = 10 bars exactly; only the anchor is open. Blocks OscillatorArtifactWindowBlock.; gates: ['OscillatorArtifactWindowBlock']

### Grimes's pullback TRIGGER (trend-line failure and recover)
- **pullbacks_continuation**: options=["project a real trend line from pivots (TrendLineBreak plus decision 17's maxAnchorSpanBars)", "break and recover of the pullback's shifted window extreme"]; recommended: The window-extreme proxy, key LevelBreakAndRecover: decision 7 already makes the shifted window extreme the default level, the proxy needs no pivot retention, and it is what both named templates use as their entry. The projected-line form stays available as TrendLineBreak and is a different rule, not this one at a parameter.; gates: ['LevelBreakAndRecover', 'Pullback', 'ComplexPullback']

### Higher-time-frame lookback multiplier
- **indicators_bands**: options=['3', '5', 'a separate optimizer input per rule']; recommended: 5, as the standing multiplier for the Grimes pass. Grimes says neighbouring time frames usually relate by a factor of three to five (G07-24). No rule in this bucket needs a new input for it: the higher-time-frame Keltner read is CloseBeyondEma at emaLength 100 / atrLookback 100 / marginAtr 2.25, placed negated — a grid point, not a rule.; gates: ['CloseOutsideKeltnerBand']

### Keltner centre line
- **indicators_bands**: options=["simple average (matches the catalog's KeltnerChannelCross)", "exponential (Grimes's own text)", 'a boolean mode input on one rule']; recommended: EXPONENTIAL, and no parameter. G03-01 quotes the book directly at p68 — '2.25 multiples of the Average True Range (ATR) around a 20-period exponential moving average' — so the merge brief's note that the book does not say is superseded by the source. The whole corpus EMA-plus-ATR-margin family (CloseBeyondEma, EmaGapBar, CloseWithinAtrOfEma) already implements it with the measured WFSafe_Xaverage; KeltnerChannelCross stays as the simple-average CROSS variant it was written to be.; gates: ['CloseOutsideKeltnerBand', 'FreeBarOutsideKeltnerBand', 'ClosesOutsideKeltnerBandCount', 'FreeBarCountInWindow', 'RidingKeltnerBandBlocksEntries', 'SpikeThroughBothKeltnerBands']

### Mechanical divergence detection
- **indicators_bands**: options=["compare the oscillator at two confirmed swing pivots (SwingHigh strength 2, the book's literal reading)", 'compare price and oscillator against their own window maxima over one lookback']; recommended: WINDOW MAXIMA: fire when high[0] >= Highest(high, divLookback)[1] AND osc[0] < Highest(osc, divLookback)[1]. It needs no pivot scan, no confirmation lag and no indexing of the indicator at a pivot bar, and the corpus already has the identical shape in VolumeDivergenceAfterClimax. The pivot form stays available as a later variant if the window form proves too loose; Grimes himself says divergences fail about as often as they work, so this is not worth the pivot machinery up front.; gates: ['MomentumDivergenceAtSwingExtreme']

### minimum stop distance
- **exits_stops**: options=['add a min-distance clamp input to every stop rule', 'treat it as a grid floor: no stop-distance input optimized below one average bar range', 'ignore it']; recommended: grid floor, enforced by the design-grid pass - ORed exits cannot clamp one another, so a per-rule input would have to be added 20 times; gates: ['MinStopDistanceAverageBarRange']

### partial profit taking (scale-outs)
- **exits_targets**: options=['model each risk-multiple tranche as a FULL exit placement and let the grid choose one level', 'add fractional-exit support to the engine', 'drop the fractions and keep only the first target']; recommended: model each tranche as a full exit placement: every exit in the corpus closes the whole position, and Grimes's 25-50 percent at 1R / down to a third by 2R is sizing, not a bar condition. Record the fractions in the rule notes only; gates: []

### Period-scoped account switches (daily loss limit, trades per period)
- **context_regime**: options=['no accessor exists; grade research and defer', 'design a new per-period counter and equity latch in the engine', 'reuse the measured MonthlyProfitTarget and MaxTradesPerSession constructions']; recommended: Reuse. The machinery exists and is measured, so neither candidate is research. `MaxTradesPerSession` already counts entries per session with a date-boundary reset (`mp <> 0 and mp <> mp[1]`, catching reversals) and caps them — Grimes's per-period trade limit is that rule verbatim, priority D. `MonthlyProfitTarget` already captures period-start equity from NetProfit + OpenPositionProfit, blocks entries and forces flat — a daily loss limit is that construction with the boundary moved to `Date <> Date[1]` and the comparison on the loss side, priority B, no new engine accessor. Week and month variants are the same rules at a different boundary test; add a `periodSelect` input only if the grid asks for it.; gates: ['DailyLossLimit', 'MaxTradesPerPeriod']

### Raschke Anti on the stochastic
- **indicators_bands**: options=['build it on the measured Stochastic chain', "drop it for Grimes's own price-structure Anti"]; recommended: held at C per the merge brief, but note the brief's premise looks stale: the register's `stochastic` row is VERIFIED (SmoothingType 1, FastK fresh, SlowK a ratio of sums, seed-filled warm-up) and StochasticCross is a working port, so building it costs one port at two lengths. Grimes explicitly prefers his price-structure form, which lives in pullbacks_continuation — if that merge carries it, this one is redundant.; gates: ['AntiStochasticSlopeDisagreement']

### Side-assignment (polarity) when Grimes's long read is a catalog rule's short read
- **ranges_levels_tests**: options=['author a second file with the sides exchanged', 'add one boolean input to the existing rule that swaps its sides', 'treat it as a duplicate and rely on the negate toggle']; recommended: NOT the third - the negate toggle gives 'not A', never the other side, and a placement carries one direction, so a fade rule and a momentum rule built on the same statistic are genuinely different rules (the catalog says so for DistanceAboveRecentLow vs PullbackFromRecentHigh). Author a second file when the rule carries real machinery (LowTouchesRecentRangeLow); add a boolean when the rule is a one-line ratio (CloseInTopOfSessionRange). Downstream buckets will hit this repeatedly on level, EMA and session rules.; gates: ['LowTouchesRecentRangeLow', 'CloseInTopOfSessionRange', 'SessionOpenPositionInRange', 'AscendingTriangleIntoLevel']

### Spring/upthrust penetration bound: floor or cap
- **ranges_levels_tests**: options=["Grimes's floor (the poke must be decisive)", "Brooks's cap (SmallBreakoutTrapReversal, a one-tick trap)", 'one rule with a two-sided band']; recommended: keep both as separate files and let the data decide - they are opposite bounds on the same bar and the two books flatly disagree, which is worth testing. Keep spring and upthrust as ONE mirrored rule: no source in this bucket gives an asymmetric test, and G16-18's own note says the short side IS the upthrust.; gates: ['SpringWithMinimumPenetration']

### Swing pivot definition and pivot order
- **swing_structure**: options=["Grimes's strict three-bar first-order pivot: high[1] > high[2] AND high[1] > high[0]", "the corpus's measured EL SwingHigh(strength): at or above the `strength` OLDER bars, strictly above the `strength` NEWER ones, confirmation lag exactly `strength`", 'a recursive pivot-of-pivots scan over a maintained pivot list for second/third-order pivots', 'an ATR-multiple zigzag as an alternative pivot series']; recommended: Use the measured `SwingHigh`/`SwingLow(strength)` primitive for every Grimes pivot. Grimes's first-order pivot IS SwingHigh at strength 1 except on a flat top, where his strict wording yields no pivot and the measured rule yields exactly one (the later of the equal bars); the measurement wins. Pivot ORDER maps onto `strength` — order 1 = strength 1, order 2 = the corpus default 2, order 3 ~ 3-5 — so second- and third-order pivots are NOT distinct rules and no recursive scan is authored. Do NOT introduce an ATR-multiple zigzag: it has no fixed confirmation lag and would fork every downstream pivot rule onto a second, incompatible pivot series. For pivot-to-pivot reads, cite the corpus's newest-first three-pivot scan (SwingPivotTarget / ShrinkingSwingIncrementsExit), which caps any 'last N legs' at 2 legs per series and guards the -1 sentinel as a bool from the scan, never as a price.; gates: ['SecondOrderPivot', 'SwingTrendHigherHighsAndLows', 'UpLegsLongerThanDownLegs', 'SwingLegExceedsAverageLeg', 'SwingPointUndercut', 'SwingTrailCappedAtMaxRisk']

### The pullback primitive
- **pullbacks_continuation**: options=["author a PullbackInProgress rule from Grimes's definition", 'treat the primitive as already on disk']; recommended: Already on disk, do not author: depth is PullbackDepthFromRecentHigh, duration PullbackDurationBars, leg count HighLowBarCount / LegCountAtLeast, 'no new extreme for N bars' BarsSinceExtremeExceeds. ### The trading-range test ('the market is in a range')

### time-stop tightening curve

### Trend test and higher-timeframe approximation
- **context_regime**: options=['EMA slope over N bars (G07-02 / G07-25 / G03-35)', 'price mostly on one side of a moving average, K of N closes (G07-01)', 'the pivot sequence of higher highs and higher lows (G03-26 / G02-02)', "Dow's latched three-state machine, up / uncertain / down (G03-27)", "the corpus's always-in direction counter (TrendDurationBars)"]; recommended: ONE mechanizable trend test: `EmaSlope` (emaLength 20, slopeLookback 5, with `slopeAtr` as the optimizer input; slopeAtr = 0 is the bare slope all three Grimes restatements give). HIGHER-TIMEFRAME APPROXIMATION: the same rule at `emaLength x 5` — a second placement, not a new rule — which is the mining brief's longer-lookback-on-the-same-bars convention with the multiplier pinned at 5. Any bucket meeting 'the higher time frame is trending' should cite EmaSlope at 5x length and grade the rule on its own merits rather than C. ### What a support/resistance level is (Grimes gives no algorithm)
- **ranges_levels_tests**: options=['the N-bar window extreme over the one-bar-shifted series, Highest(High, N)[1] / Lowest(Low, N)[1]', 'the most recent CONFIRMED swing pivot of strength S', 'the boundary of a range defined by K-bar width over ATR']; recommended: BOTH, by role, and this is already the corpus's own practice: the one-bar-shifted WINDOW EXTREME is the default for every same-bar or few-bar test (break, touch, reclaim, rejection, spring), because it needs no pivot scan and no confirmation lag - StopRunReversalBar, TouchOfRecentExtreme, NearMissLevelReversal, SmallBreakoutTrapReversal, FailedBreakoutBeyondExtreme and RangeHeightProjectionTarget all use it; the CONFIRMED SWING PIVOT of strength S is used only when the level must persist from one event to a later one (a break followed by a retest, or a counted set of touches), which is what BreakoutLevelRetest, LevelTouchCount, SwingPointTestHolds and SwingPivotTarget already do. The third option collapses into the first, since a range boundary IS the window extreme. Tolerance around a level is ALWAYS an ATR fraction (0.1-0.25 typical, 0.5 for magnets), never ticks or price points: MinMove/PriceScale are unregistered and the engine exposes no tick size.
